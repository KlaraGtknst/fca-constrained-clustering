\section{Existing World}

\begin{frame}{Running Example: Organizing BankSearch}
\begin{columns}[T,onlytextwidth]
\begin{column}{0.50\textwidth}
\textbf{Task}
\begin{itemize}
    \item Build a browsable search hierarchy for 11,000 BankSearch web pages.
    \item Help users move from broad domains to more specific document groups.
    \item Keep the hierarchy explainable, not just manually labeled.
\end{itemize}
\end{column}
\begin{column}{0.46\textwidth}
\textbf{Available sources}
\begin{itemize}
    \item A manual topic hierarchy from prior work.
    \item Document text from the corpus.
    \item Topic-model evidence extracted from the documents.
\end{itemize}
\end{column}
\end{columns}

\vspace{0.5em}
\begin{block}{Roter Faden}
Can we turn BankSearch into a hierarchy that respects expert knowledge and explains why documents belong together?
\end{block}
\end{frame}

\begin{frame}{The Manual Hierarchy Is Useful}
\begin{columns}[T,onlytextwidth]
\begin{column}{0.48\textwidth}
\begin{itemize}
    \item The manual hierarchy gives a trusted domain organization.
    \item It separates broad areas such as Finance, Science, Programming, and Sport.
    \item It provides background knowledge that a search system should not ignore.
\end{itemize}
\end{column}
\begin{column}{0.48\textwidth}
\small
\begin{tabular}{ll}
\toprule
\textbf{Domain} & \textbf{Topics} \\
\midrule
Finance & Banks, Societies, Insurance \\
Science & Astronomy, Biology \\

Sport & Soccer, Motor Racing \\
\bottomrule
\end{tabular}
\end{column}
\end{columns}

\vspace{0.5em}
\begin{alertblock}{But}
The manual hierarchy says which categories belong together, but not which shared document properties justify a cluster.
\end{alertblock}
\end{frame}

\begin{frame}{Why FCA Is the Right Candidate}
\begin{columns}[T,onlytextwidth]
\begin{column}{0.55\textwidth}
\begin{itemize}
    \item \ac{fca} concepts contain extents and intents.
    \item Extent: the documents in a cluster.
    \item Intent: the shared attributes that describe the cluster.
    \item This gives an intensional explanation for each hierarchy node.
\end{itemize}

\begin{frame}{State of the Art Around the Example}
\begin{itemize}
    \item Hierarchical text classification predicts labels inside a given taxonomy.
    \item \ac{fca}-based hierarchy generation derives concepts directly from formal contexts.
    \item Constrained clustering injects prior knowledge through constraints.
    \item \ac{mlb} constraints express hierarchical merge order in agglomerative clustering.
\end{itemize}

\vspace{0.5em}
\begin{block}{Gap}
We have data-driven \ac{fca} hierarchies and constrained clustering, but no systematic way to use \ac{mlb} expert hierarchy constraints inside \ac{fca} and compare them with topic-model concepts.
\end{block}
\end{frame}
